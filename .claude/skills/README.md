# Скиллы проекта

Здесь живут скиллы Claude Code для трекера цен. Скилл — это папка с файлом
`SKILL.md`, которую Claude подгружает сам, когда задача совпадает с описанием
из `description`.

## Структура

```
.claude/skills/
├── README.md            # этот файл
├── TEMPLATE.SKILL.md    # шаблон для копирования (сам скиллом не является)
└── <имя-скилла>/
    ├── SKILL.md         # обязательный файл: фронтматтер + инструкции
    ├── references/      # необязательно: справочники, которые читаются по мере надобности
    └── scripts/         # необязательно: вспомогательные скрипты
```

Скиллом считается только папка с `SKILL.md` внутри. Файлы, лежащие прямо в
`.claude/skills/`, не загружаются — поэтому шаблон и этот README ничему не мешают.

## Как добавить скилл

1. Скопировать шаблон в новую папку:
   ```bash
   mkdir -p .claude/skills/my-skill
   cp .claude/skills/TEMPLATE.SKILL.md .claude/skills/my-skill/SKILL.md
   ```
2. Заполнить фронтматтер и тело.
3. Перезапустить сессию Claude Code (скиллы читаются при старте) и проверить,
   что скилл виден: `/my-skill` или запрос, попадающий под `description`.

Альтернатива — скилл `skill-creator`: он умеет создавать и улучшать скиллы
интерактивно.

## Фронтматтер

```yaml
---
name: my-skill              # только строчные буквы, цифры и дефисы; совпадает с именем папки
description: >-             # 1–3 предложения: ЧТО делает и КОГДА применять
  Что делает скилл. Использовать, когда пользователь просит X, упоминает Y
  или работает с Z.
---
```

`description` — единственное, что Claude видит до загрузки скилла, поэтому в нём
должны быть слова-триггеры, которыми пользователь реально формулирует задачу.

## Соглашения

- Одна задача — один скилл; не складывать в скилл всё подряд.
- `SKILL.md` держать компактным (ориентир — до ~500 строк), длинные справочники
  выносить в `references/` и ссылаться на них из тела.
- Инструкции писать императивно и по шагам, с примерами команд.
- Имена в kebab-case: `track-prices`, а не `TrackPrices`.

## План скиллов трекера цен
